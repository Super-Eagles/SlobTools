# pgm.txt 模板
# 作用：
# 1. 模式 3 / 4 / 6 的查杀列表以本文件为准
# 2. 模式 3 / 4 的重启顺序也以本文件从上到下的顺序为准
#
# 支持三种写法：
# 1) 只写进程名
#    进程名
#    含义：查杀时按进程名匹配真实路径；重启时沿用命令行传入的启动模式，
#          并优先使用查杀时记录到的真实 exec_path 启动
#
# 2) 写绝对路径 + 启动模式
#    /绝对路径/进程名|启动模式|
#    含义：basename 作为进程名参与查杀；若进程当前没运行，重启时优先用这里的绝对路径
#
# 3) 写进程名或路径 + 启动模式 + 启动命令
#    进程名或/绝对路径/进程名|启动模式|启动命令
#    含义：该进程重启时优先使用这里单独配置的启动模式和启动命令
#
# 启动模式可填：
#   d / direct  直接启动
#               实际命令形态：
#               cd <目录> && DISPLAY=:0 nohup setsid <命令> >/dev/null 2>&1 </dev/null &
#   t / term    终端模式启动
#               实际命令形态：
#               cd <目录> && DISPLAY=:0 nohup setsid mate-terminal -e <命令> >/dev/null 2>&1 </dev/null &
#   n / none    不启动
#
# 注意：
# 1. 查杀时，只有 /proc/PID/exe 的最后一级文件名 == 这里登记的进程名，才会被认定为目标进程
# 2. 第一列如果带路径，脚本会取最后一级文件名作为进程名；重启时优先使用这条路径
# 3. 如果填写了启动命令，脚本会先切到该进程真实路径所在目录，或第一列给出的路径所在目录，再把这个命令内容塞进上面的启动骨架
# 4. 如果某个进程不需要单独命令行，建议只写进程名，或者写“绝对路径|模式|”
# 5. 参数3建议填写主进程名；主进程未运行时，脚本会给主进程补兜底启动路径
#
# ----------------------------------------
# 下面是示例，请按实际程序修改
# ----------------------------------------

# 主进程：不单独指定启动命令，沿用命令行传入的启动模式
MainNodeV3

# 程序当前没跑时，可直接靠这里的绝对路径启动
/data/td/WorkerNode|d|

# 后台启动，并带命令行参数
WorkerNode|d|./WorkerNode --config worker.ini

# 终端模式启动，并带命令行参数
UiDaemon|t|./UiDaemon --profile prod

# 只查杀，不重启
LogCollector|n|./LogCollector
